# Send a manual notification

Needs `can_create_notification_event` to create and `can_dispatch_notification_event` to send. Facility admins have both; nurses have neither.

## Create it

1. Go to **Notifications** in the facility sidebar, then **New notification**.
2. Fill in:
   - **Title** — required, internal label only, not sent to anyone
   - **Description** — optional
   - **Trigger** — only manual triggers appear. If the list is empty, no manual trigger is configured and the form cannot be submitted.
   - **Template** — only active templates appear, labelled `Name (provider)`
   - **Mark as urgent** — exempts the message from send pacing
3. Add recipients. Type two or more characters in the patient or staff picker and pick from the results. At least one is required.
4. **Create**. You land on the event's detail page.

Creating does not send anything. Recipients sit at *pending*.

## Send it

On the detail page, press **Dispatch N pending** and confirm. The count in the dialog is how many messages will go out.

You can also dispatch from the list: row menu → **Dispatch**.

Either way the response is immediate and the sending happens in the background — the toast reports how many were queued, not how many arrived.

## Watch delivery

The recipients table shows each person's latest status: pending, sent, delivered, read, or failed. The page refreshes itself while anything is unsettled.

For a failure, **See error** shows the provider's raw response — usually the fastest way to tell a bad phone number from a rejected template.

## If you never press Dispatch

It still sends. A background sweep picks up any pending recipient every couple of minutes. The Dispatch button controls *when*, not *whether*.
